# Retained integration and next useful increment

The integration points described here are implemented by Proposed0032 and
report0016: the retained reference belongs to an immutable publication version;
admission changes it atomically with live obligations; ordered subscription
updates materialize frozen replay references; work pages carry effective QoS
and RETAIN into the existing delivery machines. Producer ClientID survives its
session. The normal package contains the publish/restart/dashboard/clear demo.

Message Expiry now extends these integration points under Proposed0033:
original raw domain/tick/interval, frozen replay lifetime, per-copy transmission
certainty, shared-reference cleanup, bounded maintenance and outgoing property
patching. Unknown temporal continuity blocks fresh delivery instead of pausing
or restarting a lifetime. Its system reception and preview remain distinct from
historical incomingQoS2 fixture qualification.

One next useful functional increment is an explicitly persisted MQTT5 Will,
using the received session lifecycle authority and message admission/expiry
paths. Begin with a non-retained QoS1 Will on transport loss; do not add a new
general infrastructure or claim it implemented by this note.
