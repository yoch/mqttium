# Retained integration and next useful increment

The integration points described here are implemented by Proposed0032 and
report0016: the retained reference belongs to an immutable publication version;
admission changes it atomically with live obligations; ordered subscription
updates materialize frozen replay references; work pages carry effective QoS
and RETAIN into the existing delivery machines. Producer ClientID survives its
session. The normal package contains the publish/restart/dashboard/clear demo.

Next functional increment recommended: MQTT5 Message Expiry, starting with one
retained value that expires before a new subscription and is not replayed.
Integrate at retained/admission deadlines, frozen queued deliveries and outgoing
property encoding; preserve bounded session-time authority and shared-reference
release. It needs its own relative-interval and restart contract. Message Expiry
continues to be explicitly refused in this preview; no new infrastructure or
partial implementation is introduced here.
