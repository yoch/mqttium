# mqttiumd independent trust review

Reviewed the working tree at `49bbaaa4d1d080f458980e3498e90638e317668d` for PR 648, with base `874f298b4de7c3a13006cb1ff767dfb09e4031ac`. The review used the implementation and test source at that revision. No tests or campaigns were run for this report. The two race findings follow from reachable source orderings. Their occurrence rates were not measured.

## Findings

### P1 — TLS shutdown can discard a received normal MQTT DISCONNECT

The TLS task publishes decoded MQTT packets and write results on separate bounded channels. The reactor consumes at most four input facts per peer turn. The task can enqueue a normal DISCONNECT while the reactor processes the earlier input, then exit before the reactor polls write results. A write failure or disconnected writer channel takes the same close path as an ordered input-channel EOF. The reactor can close the peer with that DISCONNECT still queued. Deferring the close through `peer.closing` also blocks further consumption of that input queue. [Channel creation](https://github.com/yoch/mqttium/blob/49bbaaa4d1d080f458980e3498e90638e317668d/mqttiumd/crates/mqttiumd/src/net.rs#L233) · [TLS task input and exit](https://github.com/yoch/mqttium/blob/49bbaaa4d1d080f458980e3498e90638e317668d/mqttiumd/crates/mqttiumd/src/net/tls.rs#L517) · [Task terminal facts](https://github.com/yoch/mqttium/blob/49bbaaa4d1d080f458980e3498e90638e317668d/mqttiumd/crates/mqttiumd/src/net/tls.rs#L243) · [Input turn](https://github.com/yoch/mqttium/blob/49bbaaa4d1d080f458980e3498e90638e317668d/mqttiumd/crates/mqttiumd/src/runtime.rs#L2656) · [Writer-driven close](https://github.com/yoch/mqttium/blob/49bbaaa4d1d080f458980e3498e90638e317668d/mqttiumd/crates/mqttiumd/src/runtime.rs#L2822)

Processing the DISCONNECT would cancel the Will and apply any valid Session Expiry override. The competing path defaults to publishing an armed Will, which can replace a retained presence value. The secure reception tests cover an ordinary normal DISCONNECT and a TLS `close_notify` sent without MQTT DISCONNECT as separate cases. Use an ordered receive-terminal fact or require the reactor to reach the end of the inbound queue before closing from TLS writer facts. Preserve the bounded turns while draining the remaining input. ### P1 — Overlapping authorized CONNECTs can leave both transports disconnected

Two CONNECTs for the same ClientID can both pass the Will barrier before the first Open commits a Will. At intake the runtime snapshots only the existing attached generation. A negative barrier response queues Open without rechecking the attachment. After the first Open commits, the second sees the first attached and plans a takeover close and its own Open. The runtime gates submission on the old socket's disappearance. The second Open holds the singleton lifecycle flight, preventing the first transport's queued `EndSessionWill` from advancing. SQLite sees the still-armed Will and refuses the second Open with a precondition failure. [Attachment snapshot](https://github.com/yoch/mqttium/blob/49bbaaa4d1d080f458980e3498e90638e317668d/mqttiumd/crates/mqttiumd/src/runtime.rs#L2173) · [Barrier processing](https://github.com/yoch/mqttium/blob/49bbaaa4d1d080f458980e3498e90638e317668d/mqttiumd/crates/mqttiumd/src/runtime.rs#L1666) · [Barrier query](https://github.com/yoch/mqttium/blob/49bbaaa4d1d080f458980e3498e90638e317668d/mqttiumd/crates/mqttiumd/src/writer.rs#L1038) · [Core takeover planning](https://github.com/yoch/mqttium/blob/49bbaaa4d1d080f458980e3498e90638e317668d/mqttiumd/crates/mqttiumd-core/src/owner/sessions.rs#L194) · [Submission gate](https://github.com/yoch/mqttium/blob/49bbaaa4d1d080f458980e3498e90638e317668d/mqttiumd/crates/mqttiumd/src/runtime.rs#L3604) · [EndWill serialization](https://github.com/yoch/mqttium/blob/49bbaaa4d1d080f458980e3498e90638e317668d/mqttiumd/crates/mqttiumd-core/src/owner/sessions.rs#L303) · [Store Will guard](https://github.com/yoch/mqttium/blob/49bbaaa4d1d080f458980e3498e90638e317668d/mqttiumd/crates/mqttiumd-store-sqlite/src/will.rs#L292)

The first transport closes for takeover, and the second receives CONNACK 0x80 if its reply can be sent. Another CONNECT is then needed. The existing sequential takeover tests wait for the first CONNACK before the replacement starts. Serialize unresolved CONNECTs by ClientID through the attachment outcome, then re-evaluate the current attachment and Will barrier before allocating the next Open. ### P1 — Open can commit when the peer's packet limit cannot carry CONNACK

The codec accepts every nonzero peer Maximum Packet Size, and the product's success CONNACK is 24 bytes. An authorized CONNECT advertising a smaller cap can close the old transport and commit Open before the runtime rejects the oversized CONNACK. With Clean Start, the committed Open can erase the previous session's subscriptions, inbound exchanges, and owed deliveries. An Open that installs a Will can also trigger it when the unusable transport closes. The codec test checks that a tiny nonzero limit survives decoding. The runtime tests for tiny limits exercise already-unsupported CONNECTs. Check that the success frame fits before the takeover and Open, and give a bounded refusal where it fits. ### P2 — Normal TLS closure omits the server `close_notify`

The TLS task observes a peer TLS close alert and eventually shuts down the TCP socket. The broker never sends a TLS close alert on this path or on its ordinary transport close path. The pinned rustls receive path records the peer alert and leaves sending a close alert to the caller. Clients that perform orderly TLS shutdown can therefore report abrupt TLS EOF. The existing unwrap test accepts an SSL or connection exception and checks only the MQTT Will effect. Add a bounded `close_notify` flush to the normal TLS shutdown path with transport closure as the deadline fallback. [Peer alert](https://github.com/yoch/mqttium/blob/49bbaaa4d1d080f458980e3498e90638e317668d/mqttiumd/crates/mqttiumd/src/net/tls.rs#L104) · [Task shutdown](https://github.com/yoch/mqttium/blob/49bbaaa4d1d080f458980e3498e90638e317668d/mqttiumd/crates/mqttiumd/src/net/tls.rs#L243) · [Socket shutdown](https://github.com/yoch/mqttium/blob/49bbaaa4d1d080f458980e3498e90638e317668d/mqttiumd/crates/mqttiumd/src/net.rs#L127) · [rustls alert handling](/workspace/.mqttiumd-tools/cargo/registry/src/index.crates.io-1949cf8c6b5b557f/rustls-0.23.46/src/common_state.rs:584) · [Unwrap test](https://github.com/yoch/mqttium/blob/49bbaaa4d1d080f458980e3498e90638e317668d/mqttiumd/tests/system/secure_reception.py#L374)
