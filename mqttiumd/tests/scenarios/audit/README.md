# Scenarios of the audit of the first wave

Regressions of the findings in `docs/reception/open-conditions.md`, played
by the runner of lot L4 (`tools/run_campaign.sh`).

| Scenario | Finding | What it plays | Limits |
| - | - | - | - |
| `F3-steady-lag.json` (`F3-STEADY-LAG`) | F3 | The first `Persist` commits and its result is lost; seven resolutions run, one per deadline, and each answer is held; the answer to the first is handed over after six newer resolutions ran. The exchange must commit: PUBREC follows the late answer | One late answer, with a lag of six. The lag is bounded by the result slots of the fixture (8: seven held answers and one command in transit). A steady regime where every answer arrives four resolutions late is not written: the scenario would have to know in advance at which delivery the core progresses, since no resolution follows a commit. Its control is mutation `m4` of `tests/mutants/loop/`: the run stops at step 19 with nothing eligible, the bench writes `StepBlocked` (`quiescent`), and the oracle rejects it as FAIL on `scenario_reaches_its_end` |
| `F3-permanent.json` (`F3-PERMANENT`) | F3 (decision 0018) | The example `scenario-permanent-delay` of the contracts, unchanged: the result of the first `Persist` is lost, then every answer to a resolution of `pub_A` is held from its first occurrence with a lag of six, and the wait for PUBREC fires the deadlines itself (`fire_deadlines`). The exchange must still commit | Refused before anything is written, on both stores: the store adapter does not repeat a fault from an occurrence yet (lot L2), so `from_occurrence`, `expected_hits_at_least` and `lag` are not played. `tests/bench_unplayed.rs` checks that the file stays the example and stays refused. Its control by mutation `m4` comes once it is played |
| `P1-02b-interposed.json` (`P1-02B-INTERPOSED`) | Order and cause (lot L3) | P1-02b with one more step: the supervisor inspects the durable state after the late unknown answer reaches the core and before the peer sends PUBREL. The supervisor had read that answer, so its record names it, and the PUBREL names the inspection: the PUBREL descends from the unknown answer through records of the bench only. `terminal_knowledge_never_regresses` must count reactions of the product alone: PASS. On the oracle before the separation of order and cause it was a FAIL on the inspection record itself | The inspection is the only record of the bench between the answer and the PUBREL; `tests/bench_p1_02b.rs` checks that the file stays P1-02b with that one step and that the causes are as described |
