# Wildcard selection, No Local and subscription cuts

`MWildcardRouting` is one finite specification model of recipient selection
for the bounded non-shared subscription profile. It explores every order of
scanning a small route set, independently checks the resulting destinations
and QoS, and interleaves one atomic subscription mutation with selection or
with already admitted work. Existing models and their expected outcomes are
unchanged. This model is not a Rust refinement or an MQTT certification.

```bash
# From the repository root, with the pinned tools:
python tools/formal/run_tlc.py --models-dir mqttiumd/models/wildcard-routing --list
python tools/formal/run_tlc.py --models-dir mqttiumd/models/wildcard-routing
cd mqttiumd
python models/check_models.py
python -m unittest discover -s models -p 'test_*.py'
cargo test --locked -p mqttiumd-contract --test topic_generated
```

## Normative boundary

The reference is the [OASIS MQTT5 standard](https://docs.oasis-open.org/mqtt/mqtt/v5.0/os/mqtt-v5.0-os.html),
especially sections3.3.4,3.8.3,3.8.4 and4.7.

- `#` occupies the complete final filter level and includes its parent and zero
  or more child levels; `+` occupies a complete single level. Empty levels are
  actual levels, while a missing level is not an empty one
  (MQTT-4.7.1-1/-2).
- A filter whose first character is `#` or `+` does not match a Topic Name
  beginning with `$`. Explicit system prefixes such as `$SYS/#` can match it
  (MQTT-4.7.2-1).
- Topic/filter matching preserves case, empty levels and the exact UTF-8
  spelling; no Unicode normalization or substitution is allowed
  (MQTT-4.7.3-4).
- No Local excludes an individual subscription when the publishing connection
  has the target connection's ClientID (MQTT-3.8.3-3). Group the remaining
  matches by destination and use the maximum granted QoS, capped by the
  published QoS (MQTT-3.3.4-2 and MQTT-3.8.4-8). One canonical copy is legal;
  the additional copies allowed for overlapping filters are optional.
- Replacing an identical non-shared filter replaces its options without losing
  Application Messages (MQTT-3.8.4-3/-4). Multiple filters in one SUBSCRIBE
  behave as a sequence, with ordered results in one SUBACK
  (MQTT-3.8.4-5/-6). A later replacement/unsubscribe cannot retroactively change
  already admitted responsibilities.

ClientID comparison is represented by the two durable session identities.
The correspondence assumes the product establishes a single active incarnation
per ClientID at the routing cut and rejects stale source-incarnation commands.
There is no historical rerouting to a later incarnation using the same name.
The lifecycle and receipt models/tests retain responsibility for those guards;
a refreshed ClientID cache is not an authority in this model.

Shared subscriptions and Subscription Identifiers are outside this tranche.
No Local on a shared subscription, requested QoS3, Retain Handling3 and nonzero
reserved option bits are protocol errors. These parser rules are concrete
codec obligations, not state variables here. The profile continues to advertise
Retain Available0, Subscription Identifiers Available0 and Shared Subscription
Available0. Its Wildcard Subscription Available must be1 or omitted once
wildcards are accepted. No Local has no separate availability property.

Retain As Published and Retain Handling do not appear in this selection model.
The standard explicitly notes that, with Retain Available0, all their valid
values have the same behavior: no stored retained messages at subscription and
RETAIN0 for forwarded messages. The product must document any accepted
options under that restriction; this model does not implement retained storage.

## Independent finite matching relation

The model contains an explicit relation, not a recursive or byte-level matcher.
Each named filter has the following bytes:

| Symbol | Filter |
| - | - |
| `exact` | `a/b` |
| `plus` | `a/+` |
| `hash` | `a/#` |
| `all` | `#` |
| `two-level` | `+/b` |
| `system` | `$SYS/#` |

The eight named topics are `leaf=a/b`, `empty-child=a/`, `parent=a`,
`system-parent=$SYS`, `system-leaf=$SYS/status`, `nested-dollar=a/$b`,
`leading-empty=/b` and `deep=a//b`. `MatchPairs` lists the expected matches
literally. It encodes the parent/empty-level/system examples independently of
the production matcher. It is a finite example domain, not the full grammar.

The complementary Rust integration test is
[`topic_generated.rs`](../../crates/mqttiumd-contract/tests/topic_generated.rs).
It constructs909 filters from symbolic literal/one-level/final-many-level
productions. Expected languages are generated by literal substitution,
enumerating `+` from a finite alphabet and enumerating `#` suffix lengths.
It never parses a wire filter or splits a topic to derive the expectation.
Root wildcard productions use a user-root alphabet, independently excluding
system-root values. The583 nonempty topics preserve empty levels, `$SYS`,
`$other`, `é`, the distinct decomposed `e`+combining-acute and `温度`.
The resulting529,947 comparisons exercise the actual public matcher.
Malformed-placement, NUL and invalid-UTF8 cases and the separate unsupported
shared-subscription profile are checked distinctly. The generated workload
stops at three levels; numeric packet/field limits and deeper bounded inputs
remain concrete codec/store tests.

## Reduction, updates and frozen responsibilities

The initial six-entry domain has five subscriptions. Session1 has an exact
QoS1/NoLocal1 match and an overlapping `a/#` QoS0/NoLocal0 match. Session2 has
three overlapping matches with granted QoS0/1. A sixth slot can install the
explicit system filter for Session1.

`Begin` takes a route-revision snapshot and independently computes the expected
answer using a set of individually eligible entries. `Scan` chooses any
unvisited entry, applies No Local, and combines that destination's offered
QoS using maximum. The independently stated expected answer uses set
comprehension and existential selection of a QoS1 grant rather than that fold.
Each destination has one copy count and one offered QoS. Visiting another
matching subscription combines its QoS and cannot create another copy.
Destination keys have a fixed order1,2; canonical byte encoding/order in Rust
is a separate test obligation, not a sorting algorithm proved by this model.

`Prepare` freezes that finite result. `Commit` accepts it only while the
captured route revision is current. An intervening replacement/removal makes
this attempt a certain rejection, leaving no admitted recipient decision.
The existing command/receipt machinery governs any subsequent attempt; this
model does not retry unknown commands under a new identity.

`Update` represents one atomic upsert or unsubscribe of one existing key. Its
projection change and revision advance are one step, with no observable delete
then recreate gap. Wire-order duplicate entries within a multi-filter packet,
per-filter SUBACK/UNSUBACK results, canonical recipe comparison, lost replies
and receipt collection remain concrete tests and the existing receipt model.
The map representation assumes uniqueness of a subscription key; it is not a
proof of the Rust map/SQLite key implementation.

After acceptance, `decision` represents the frozen destinations/QoS of that
publication. Later updates do not modify it. For durable incoming QoS1/2 this
corresponds to admitted obligations. For initially QoS0 it is only the accepted
volatile selection: `Commit` is not a disk commit and makes no durability or
acknowledgement claim for that path. Outbox reservations, delivery consumption,
network generations and recipient ACKs retain their separate tests/models.

There is one publication attempt, two sessions, six route cells, at most one
subscription change and bounded counters. `hExpected`, `hFrozen` and
`hStaleCut` are verifier histories, not runtime tables. No normal action guard
reads them. No fairness or latency is assumed, and `Idle` permits no progress.

## Expected outcomes

| Configuration | Expected result |
| - | - |
| `safety` | Six invariants pass for all source/topic/published-QoS choices, every route visitation order and one update before, during or after selection. |
| `mut-duplicate-target` | `OnePerDestination` fails when each matching entry allocates another copy instead of reusing the destination accumulator. |
| `mut-local-after-max` | `EligibleMaximumQoS` fails when an excluded local QoS1 match participates in the reduction alongside an eligible QoS0 match. |
| `mut-last-qos-wins` | `EligibleMaximumQoS` fails when route enumeration order can overwrite a higher eligible QoS with a lower one. |
| `mut-ignore-cut` | `CurrentRoutingCut` fails when a prepared result commits after the projection changes. |
| `mut-retroactive` | `FrozenResponsibilities` fails when a subscription update reroutes already admitted work. |
| `reach-overlap` | `NoOverlapWitness` is intentionally violated by source1/QoS2/topic`a/b`, yielding one QoS0 copy to itself and one QoS1 copy to Session2. |

The runner requires the exact declared invariant for each negative case.
Syntax errors, another failure or incomplete exploration are not detections.
These specification mutations do not imply a compiled implementation mutation
was detected or that a system run was independently oracle-qualified.

## Correspondence

The sidecar remains `specification` with `tests: []`; no exact TLC-to-Rust
counterexample trace refinement is registered. This model-only lot's execution
receipt is distinct from the integrator's final content-specific verification.

| Model action | Implementation predicate | Replay |
| - | - | - |
| `Begin` | Snapshot one routing cut and publisher identity before preparing recipients. | Core/store wildcard selection tests; independent generated matcher test covers the full bounded grammar rather than this fixed table. |
| `Scan` | Match a filter, exclude No Local per match, deduplicate by durable destination and take maximum eligible QoS before capping by publish QoS. | Overlap/self-publish mixed-option tests; duplicate/local-after-max/last-qos-wins configurations. |
| `Prepare` | A canonical recipient plan retains the route revision it used. | Existing prepared-transition and canonical-admission guard tests, extended to overlapping filters. |
| `Commit` | Current revision and canonical recipient set authorize acceptance; stale cuts cannot be reinterpreted. | Store route-revision/target-set refusal tests and `mut-ignore-cut`; genuine unknown results are a separate concrete reception. |
| `Update` | Replace/remove exactly one subscription key atomically; admitted obligations retain their original destination/QoS. | Duplicate-filter update, unsubscribe-exact-key and old-obligation tests; `mut-retroactive`. |
| `Idle` | No fairness, universal timing or automatic progress assumption. | Every configuration; real-client/SQLite receptions retain their own bounded scope. |
